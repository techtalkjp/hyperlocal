# 2026-10-18 Shannon 監査記録

hyperlocal の公開サイトと管理画面について、隔離したダミーデータ環境で脆弱性を調べた。修正は [PR #81](https://github.com/techtalkjp/hyperlocal/pull/81) と [PR #82](https://github.com/techtalkjp/hyperlocal/pull/82) でマージし、両 Worker のデプロイを確認した。2026-10-18 にシャードを新版 `202610181230` で公開し、旧版も検査した。

## 結果

| 対象 | Shannon の動的実証 | 追加で確認した問題 | 対応 |
| --- | --- | --- | --- |
| 管理画面 | `/logout` がセッションを無効化しない問題を1件実証 | 本番ドメインの HTTP `/login` が 200 を返し、HTTPS 応答に HSTS がない | 未使用の `/logout` ルートを削除。Worker で本番ホストの HTTP を HTTPS へ転送し、HSTS と HTTPS の認証基準 URL を設定 |
| 公開サイト | 実証済み0件 | 静的解析で、下書きの本文とタイトルをガイド用シャードから公開しうる経路を確認。合成データで再現。本番ドメインの HTTP `/` は 200 | 公開済み記事だけをシャードとインデックスへ出力。読込時にも公開状態を検査。Worker に HTTPS 転送と HSTS を追加 |

管理画面の最終報告では、注入、XSS、権限、SSRF の実証済み問題はなかった。公開サイトの最終報告でも、対象の5分類に実証済み問題はなかった。「0件」はこの隔離環境での実証結果であり、下書きシャードの静的解析結果を否定するものではない。

## 追加の修正

- コンテンツの D1 同期から認証テーブルを除外し、古い認証 SQL ダンプを適用前に拒否する。SQL 文の分割を引用符に対応させ、記事や店舗名の改行で同期が壊れる問題を直した。
- DB のデバッグログからバインド値を除き、下書き本文などがログへ出る条件をなくした。
- ローカルの記事保存スクリプトで area と scene の ID を検証し、保存先が記事ディレクトリの外へ出る入力を拒否する。
- 店舗の外部リンクは HTTPS の `tabelog.com` だけを表示する。リンクを表示しない場合は Google Maps ボタンを1列で表示する。
- Hotpepper の候補に座標の欠損や非数値がある場合は、距離による突き合わせから除外する。
- Tabelog のページ送り・店舗詳細・レビューの URL は HTTPS の `tabelog.com` だけに限定する。Google、Tabelog、Hotpepper の写真は確認済みの配信ホストだけを取り込み、表示時にも検証する。
- 初回登録の管理者は `ADMIN_EMAILS` の先頭アドレスに固定する。翻訳結果のレビュー番号は、要求した番号との一対一対応を検証し、合わない場合は原文に戻す。

## 本番確認

- `main` の CI、DB マイグレーション、公開サイトと管理画面のデプロイは成功した。両本番ホストの HTTP は HTTPS へ 308 で転送され、HTTPS は HSTS `max-age=31536000` を返した。
- 管理画面の実行時 `BETTER_AUTH_URL` は `https://admin.hyper-local.app`。認証開始時の state Cookie と `sign-out` API が消去する session Cookie は、どちらも `Secure`、`HttpOnly`、`SameSite=Lax` を持つ。認証済みユーザーの Google OAuth 全体とセッション失効は、本番で実証していない。
- R2 の旧版11版にあるガイド本文2,090件は全件 `published`。ガイド一覧950ファイルの全項目は同じ版の公開済みガイド本文を参照していた。削除対象はなかった。
- 現行 R2 と staging DB のシャードは、ガイド一覧95ファイル以外のハッシュがすべて一致した。staging DB から全種類15,680ファイルを新版 `202610181230` に出力・公開し、キャッシュ更新 API は 200 を返した。公開マニフェストの新版への切替、公開 URL のガイド190件と一覧95件のハッシュ・公開状態、ガイドページの 200 応答を確認した。

## 継続運用

- ガイドは公開状態を確認してからシャードへ出力する。公開時は既存版を上書きせず、新版で全種類を出力し、ガイドとガイド一覧を一緒に更新する。公開前に各種類の件数と現行マニフェストとの差を確認し、公開後にマニフェスト、ガイドの状態、キャッシュ更新を確認する。
- D1 へのコンテンツ同期は `places`、`place_listings`、`localized_places`、`area_articles` だけを扱う。`export-sql.ts` は空の出力先を使い、`d1-apply.ts` に認証テーブルの SQL ファイルを渡さない。
- Crawler が取得する Tabelog のリンクは HTTPS の `tabelog.com` に限定する。写真配信元が変わる場合は実データを確認して許可リストを更新する。現在確認したホストは `lh3.googleusercontent.com`、`tblg.k-img.com`、`imgfp.hotp.jp`。

## 方法と限界

完了した監査は2件で、どちらも Shannon の `gpt-6-sol` を使い、実証を有効にした。作業領域は `hyperlocal-admin-20261018` と `hyperlocal-web-20261018-r3`。元の HEAD を別ディレクトリへ複製し、ダミーの SQLite と認証セッションを入れた Docker 内のアプリだけを動的試験の対象にした。アプリ用コンテナから外部ネットワークへ出られない設定にした。本番データや本番の認証情報は試験環境へ入れていない。

試験アプリは Cloudflare Workers/D1 の本番実行環境ではなく、Node の開発サーバーとローカル SQLite で動かした。管理画面のログインには試験専用の補助経路を使い、Google OAuth 全体は検証していない。公開サイトの試験環境には R2 の実データがないため、下書きシャードの漏えいは Shannon の動的実証に至っていない。別途、本番 R2 の旧版と新版のオブジェクト、公開サイトと管理画面の応答を確認した。

修正後は対象テスト、各対象パッケージの型チェック・整形・lint、管理画面の本番ビルドを確認した。lint に残る警告は既存のもの。Shannon の完全な報告は各作業領域の `.shannon/deliverables/comprehensive_security_assessment_report.md`、静的解析は `.shannon/capella/report.md` にある。
