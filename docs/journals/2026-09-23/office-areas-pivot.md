# 企画の見直しとオフィス街9エリアの追加

## 経緯

Hyperlocal はもともとインバウンド向けに、ひとりで作れるコンテンツで広告収入を得ることを狙ったサービスだった。しかし Google のインデックスが壊滅し(9月15日の記録を参照)、直近28日の実績はクリック0、表示1という状態で、当初の前提は成り立っていない。

そこで企画をゼロベースで見直した。結論は、軸を「エリア別ランキングサイト」から「東京のオフィス街で、今日これからランチや夜にどこへ行くかを即答するツール」へ移すことである。まず自分と周りの人が使えること、次に ChatGPT や Claude(MCP)、Slack から呼べること、その先で SEO やインバウンドが副産物として戻ってくることを期待する。課金や B2B は考えない。既存の URL 構造は SEO 資産として温存する。

## 現状の把握で分かったこと

既存の19エリアは浅草・上野・築地・空港などインバウンド観光地寄りで、オフィス街の比率が低かった。また、位置情報を使う機能は「選んだエリア内の店を距離順に並べ替える」だけで、エリア横断の現在地検索、検索窓、営業中フィルタ、PWA はいずれも無かった。「いま・ここで決めたい」体験と噛み合っていないのは構造的な問題である。

データ経路についても整理した。本番 D1 の内容は `data/staging.db` と完全に一致しており、クロール → transform → ingestTabelog(staging.db へ)→ localize → `export-sql --upsert` → D1、という流れが正規ルートである。旧 Turso から作った `production-replica.db` は既に古く、参照すべきではない。

## 追加したエリア

IT 企業とスタートアップの集積地から、既存エリアと重ならない9か所を選んだ。五反田、目黒、中目黒、恵比寿、神田、秋葉原、麹町(半蔵門を含む)、田町、浜松町である。食べログの駅コードは各サブエリアページから取得し、半径500mの `LstRange=SG` で統一した。エリア定義の `radius` はパイプラインでは使われず表示専用であることも確認した。

クロールは7,215ページ、失敗0で、新規6,864店のデータを取り込んだ。transform を通したランキング対象は9エリアで1,906リスティング、ingest では新規919店、更新1,966店だった。座標は国土地理院のジオコーダで補完し、欠損はゼロである。翻訳は自分用が目的なので当面 ja と en の2言語に限定し、他の3言語は必要になってから追加する。

## パイプラインへの変更

これまで `crawlTabelog` は `--all` しか実質使えず、実行のたびにデータセットを全消去していた。エリアを追加するたびに全件クロールし直すのは無駄なので、`--area` でエリアを指定でき、その場合は既存データセットに追記する形に変えた。追記による重複は DuckDB 側の `crawled_restaurants` ビューで、同じ URL とエリアの組についてファイル名(クロール順)が最新の1件を採ることで吸収している。

`localize` には `--langs` を追加し、翻訳先言語を限定できるようにした。

D1 への反映では `wrangler d1 execute --file` が使えないことが分かった。数十MBのファイルは import API の処理が長引き、15分ほどで認証エラーになる。さらに小さく分割しても、wrangler の SQL 分割器が JSON 列に含まれるバックスラッシュ(`\n` のリテラル)で誤動作し、構文エラーを起こす。そのため D1 の REST `/query` エンドポイントに直接、行頭の `INSERT INTO` を文境界として40文ずつ投げるスクリプト `apps/crawler/src/scripts/d1-apply.ts` を用意した。認証は wrangler login 済みの OAuth トークンを流用する。これで37,619文を適用し、D1 の件数は staging と一致した(places 3,155、place_listings 5,006、localized_places 29,458、28エリア)。

R2 shard は版 `2026092312` として14,526ファイルを公開した。

## 残っている作業

エッジキャッシュの purge は `PURGE_SECRET` がローカルに無いため未実施である。トップとエリアページは最長1日キャッシュされるので、すぐ反映したい場合は手動で purge する必要がある。

Phase 1 の残りは、クエリエンジンを `packages/` へ切り出すこと、トップを現在地起点にして営業中フィルタと徒歩分表示を付けること、PWA 化である。その後に MCP サーバーと Slack 連携を続ける。
